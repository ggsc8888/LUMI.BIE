# LUMI 发布台

给多条产品线排每周的社交媒体内容：记录进展和热点、写草稿、管素材和保密规则，过完四道确认之后，由管理员亲手发布。Instagram、Facebook 主页、YouTube 可以连接账号后直接发；小红书和 TikTok 登记账号，在平台里手动发。

每个空间（一个 Clerk 组织，或者没有组织的个人）有完全独立的一套：产品线、账号、素材、保密规则、每周内容和平台授权。

## 它会做什么，不会做什么

- **会做**：一张“产品线 × 平台”的周排期；素材要管理员同意才能用；保密词自动扫描；借了热点要核对原文；成品要管理员看过；四道确认全过才能通过审核。
- **会做**：管理员点“发布”后，用连接好的账号把成品和文案发出去，并把链接记回这条内容。服务器在发出去之前会把四道确认重新检查一遍。
- **不会做**：不会自己定时发布，不会替你写文案或做图做视频，不保存任何平台的密码。
- 发布之后，平台没有回应时不会自动重发：会提示你先去平台上核对，再决定要不要重试。

## 本地预览

需要 Node 24（22 也能跑）。

```bash
npm install
npm run build      # 打包浏览器端的上传组件
npm run dev        # http://localhost:4173，免登录，数据只在内存里
npm test           # 规则、租户隔离、连接和发布流程的测试（平台用替身）
```

`npm run dev -- --seed 导出文件.json` 可以带着一份导出数据启动。本地预览不连接 Clerk、Blob 和任何平台。

## 部署到 Vercel

1. 在 Vercel 新建项目，导入这个仓库。框架选 Other，其余保持默认（`vercel.json` 已经写好）。
2. 在项目的 Storage 里新建一个 **Blob** 存储，访问方式选 **Private**，连接到这个项目。Vercel 会自动加上 `BLOB_READ_WRITE_TOKEN`。建议单独建一个，不要和别的站点共用。
3. 绑定域名（见下面“登录”一节关于域名的说明）。
4. 按下表填环境变量，然后重新部署。
5. 打开站点。缺哪个变量，页面会直接列出来。

生产域名要保持公开可访问：Instagram 和 Facebook 需要从 `/api/media` 取成品文件（链接带签名、30 分钟失效）。如果给生产环境开了 Vercel 的访问保护，这两个平台会取不到文件。

### 环境变量

密钥只填在 Vercel 的环境变量里，不要写进仓库，也不要发在聊天里。

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `CLERK_PUBLISHABLE_KEY` | 是 | Clerk 应用的 Publishable key（`pk_live_…` 或 `pk_test_…`）。不需要 Secret key。 |
| `LUMI_PUBLISH_ORIGIN` | 是 | 站点的完整地址，例如 `https://publish.example.com`，结尾不带斜杠。必须和浏览器里打开的地址完全一致。 |
| `LUMI_PUBLISH_SECRET` | 是 | 至少 32 位的随机字符串，用来加密平台令牌和签名链接。可以用 `openssl rand -base64 48` 生成。**换掉它，所有已连接的账号都要重新连接。** |
| `BLOB_READ_WRITE_TOKEN` | 是 | 连接 Blob 存储后自动出现。 |
| `LUMI_PUBLISH_ALLOW` | 否 | 允许使用这个站点的 Clerk 编号，逗号分隔，可以是人（`user_…`）或组织（`org_…`）。不填就是所有能登录的人都能用（各自一个独立空间）。 |
| `INSTAGRAM_APP_ID` / `INSTAGRAM_APP_SECRET` | 否 | Instagram 登录用的应用编号和密钥。不填则 Instagram 只能手动发。 |
| `META_APP_ID` / `META_APP_SECRET` | 否 | Facebook 登录用的应用编号和密钥。不填则 Facebook 只能手动发。 |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | 否 | Google OAuth 客户端。不填则 YouTube 只能手动发。 |
| `META_GRAPH_VERSION` | 否 | Graph API 版本，默认 `v27.0`。 |

### 登录（Clerk）

- 页面从 Clerk 实例加载登录组件，服务器用实例公开的 JWKS 校验会话，不保存 Clerk 的密钥。
- **域名**：正式环境的 Clerk 应用（`pk_live_`）绑定在一个主域名上。这个站点如果放在同一主域名的子域名下，可以直接沿用同一个 Clerk 应用；换一个域名，就需要另建一个 Clerk 应用。开发环境的应用（`pk_test_`）不限域名，适合先试用。
- **共用 Clerk 应用时**，那个应用里的所有用户都能登录这里（各自得到一个空的个人空间）。只想自己或自己的团队用，就填 `LUMI_PUBLISH_ALLOW`。自己的编号在“产品线与账号”页最下面能看到。
- **团队**：在 Clerk 里打开 Organizations 后，一个组织就是一个共用的空间。组织管理员可以同意素材、确认、审核、连接账号和发布；普通成员只能写草稿、加素材和进展。没开 Organizations 时，每个人只有自己的个人空间。

## 连接三个平台

点“连接”会跳到平台自己的页面，在那里登录要连的账号并点允许。这里只拿到一枚能发内容的令牌，随时可以断开。每条产品线在每个平台各连一个账号。

每个平台需要你先用自己的账号建一个开发者应用，把下面的回调地址填进去。把 `https://你的域名` 换成 `LUMI_PUBLISH_ORIGIN` 的值。

以下平台规则是 2026-11-17 核对官方文档时的情况，平台会改，以它们的文档为准。

### Instagram

- 在 Meta for Developers 建一个应用，添加 Instagram 产品，选择“用 Instagram 登录”的接入方式。
- 回调地址（OAuth redirect URI）：`https://你的域名/api/callback/instagram`
- 把页面上显示的 **Instagram 应用编号和密钥**填进 `INSTAGRAM_APP_ID` / `INSTAGRAM_APP_SECRET`。它们和 Meta 应用本身的编号不是同一组。
- 要用到的权限：`instagram_business_basic`、`instagram_business_content_publish`。
- 账号必须是专业账号（商家或创作者）。
- 只发自己的账号时用标准权限即可，不需要应用审核；但每个 Instagram 账号都要在应用的角色里加成 Instagram 测试者，并在 Instagram 的设置里接受邀请。
- 能发的形式：单张图片（**只收 JPEG**）和 Reels 视频。多图轮播暂不支持，请手动发。
- 授权 60 天有效，临近到期时发布会自动续期；超过 60 天没用过就要重新连接。

### Facebook 主页

- 同一个 Meta 应用里添加 Facebook 登录。
- 回调地址：`https://你的域名/api/callback/facebook`
- 应用设置里的应用编号和密钥填进 `META_APP_ID` / `META_APP_SECRET`。
- 要用到的权限：`pages_show_list`、`pages_read_engagement`、`pages_manage_posts`。
- 只能发到主页，不能发到个人号。授权的 Facebook 账号要对主页有完整管理权限。一个账号下有多个主页时，授权后会让你选一个连到这条产品线。
- **应用处在开发模式时，通过接口发的帖子只有应用里有角色的人看得到。**要让所有人看到，需要把应用切到上线模式（要填隐私政策链接）。正式发之前先用一条不敏感的内容确认对外可见。
- 能发的形式：纯文字、单图、Reels 视频。

### YouTube

- 在 Google Cloud 建一个项目，启用 YouTube Data API v3。
- 建一个 OAuth 客户端，类型选 Web 应用，授权重定向地址：`https://你的域名/api/callback/youtube`
- 客户端编号和密钥填进 `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`。
- **把 OAuth 同意屏幕的发布状态改成“正式版（In production）”。**停留在“测试”状态时，授权会在 7 天后失效，每周都要重新连接。未经验证的应用在授权时会出现一个提示页，点“高级”继续即可。
- 用拥有频道的 Google 账号授权。
- 视频由服务器转交给 YouTube，单个文件上限 256 MB；更大的请在 YouTube 工作室里手动上传。发布时可以选公开、不公开列出或仅自己可见。第一条建议先用“不公开列出”试一次。

### 小红书、TikTok

小红书没有开放的发布接口；TikTok 的发布接口在通过审核之前只能发成仅自己可见。这两个平台目前只登记账号，发布时在平台里手动发，再回来点“我已经发出去了”。

### 给别人的账号用

上面的做法只覆盖“应用的拥有者发自己的账号”。要让别的团队连接他们自己的账号，Meta 需要应用审核和企业认证，Google 需要 OAuth 验证，TikTok 需要审核。站点本身已经按多空间设计，这一步是各平台的审批。

## 安全设计

- **空间隔离**：空间编号只取自校验过的登录会话，请求里带的任何编号都不算数。每个空间的数据放在各自的路径下。
- **角色**：同意素材、三项人工确认、审核、连接账号、发布，都只有管理员能做，并且在服务器上检查，页面只是把按钮关掉。
- **发布前复查**：发布时服务器重新检查四道确认、成品和授权。文案改了、素材的同意被收回、保密词新增后命中，已通过的内容都发不出去。
- **平台令牌**：用 `LUMI_PUBLISH_SECRET` 派生出每个空间自己的密钥加密后保存，只在服务器上解开，不会发到浏览器，也不写进日志。
- **连接流程**：标准的授权码流程；`state` 加密并绑定发起连接的那个浏览器，别人拿到链接也完成不了。
- **成品文件**：放在私有存储里；预览和平台取文件都用带签名、会过期的链接。
- **记录**：审核、同意素材、连接、断开、发布都会记一条（谁、什么时候）。

## 数据放在哪里

私有 Blob 存储，每个空间一个目录：

```
lumi-publish/v1/{空间编号}/state.json              # 产品线、内容、素材、进展、账号、记录，以及加密后的平台令牌
lumi-publish/v1/{空间编号}/media/{内容编号}/…       # 成品图片和视频
```

每个空间的数据放在一个文件里：打开页面读一次，保存一次是一读一写。写入时带版本校验，两个人同时保存不会互相覆盖。

**用量**：Blob 按调用次数计费。页面开着时每分钟读一次，每次保存一读一写，上传一个成品算一次写入。Vercel 免费版（Hobby）每月包含的 Blob 读写次数不多，每天开着页面工作好几个小时、多人一起用时可能会用完；超出后要等下个周期或升级到 Pro。Pro 下这点用量的费用可以忽略。

## 导入

“产品线与账号”页可以从 JSON 文件导入：

```json
{ "brands": { "编号": { … } }, "assets": { … }, "signals": { … }, "accounts": { … }, "posts": { … } }
```

导入的每一条都按和手动编辑同样的规则校验；“已通过”要在这里重新满足四道确认才会成立。

## 目录

```
api/            Vercel 函数入口（app、media、三个平台的回调）
server/         登录校验、存储、规则、连接、发布、各平台的调用
public/         页面（index.html、app.js、styles.css）和前后端共用的 shared/gates.js
scripts/        build.mjs（打包上传组件）、dev.mjs（本地预览）
tests/          node --test
```

## 还没有在真实环境里验证过的部分

代码里的测试用替身代替了外部服务。下面这些第一次上线时需要实际走一遍：

- Clerk 登录和组织切换（本地只用替身验证了页面的启动流程）。
- Vercel Blob 的读写、并发写入时的冲突处理、浏览器直传大文件。
- 三个平台的授权和发布。请求是按官方文档写的，但没有对真实接口跑过。每个平台第一次发布请用不敏感的内容。
